# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Do not make any changes until you have 95% confidence in what you need to build. Ask me follow-up questions until you reach that confidence.

## What this is

A set of independent scrapers that collect financial/energy-market news coverage from social platforms (X/Twitter, YouTube, Telegram, Reddit, TikTok, Truth Social) into a shared JSON record schema, for downstream sentiment/NLP processing (e.g. FinBERT). Each platform scraper is a standalone script driven by keyword/account config files, sharing two local modules for logging, dedup, and quality scoring.

## Running the scrapers

```bash
pip install -r requirements.txt --break-system-packages
python twtr-scraper.py     # X/Twitter — no CLI args
python yt-scraper.py       # YouTube — no CLI args
python tel-scraper.py      # Telegram — no CLI args, needs TELEGRAM_API_ID/TELEGRAM_API_HASH
python reddit-scraper.py   # Reddit — no CLI args, needs REDDIT_CLIENT_ID/REDDIT_CLIENT_SECRET
python tiktok-scraper.py   # TikTok — no CLI args
python truth-scraper.py    # Truth Social — no CLI args, needs TRUTHSOCIAL_USERNAME/TRUTHSOCIAL_PASSWORD
```

There is no test suite, build step, or linter configured in this repo. The exceptions are two assert-based self-checks. `selfcheck_twtr_retry.py` (`python selfcheck_twtr_retry.py`) covers `twtr-scraper.py`'s syndication block/retry path — that a 429 and a challenge page raise `_SyndicationBlocked` while a genuinely empty timeline returns `[]`, and that `_scrape_account_list` defers blocked accounts for a retry pass instead of dropping them; run it after touching `_syndication_timeline`, `discover_account_tweet_refs`, or the account loop. It stubs `urlopen` and makes no network calls. `selfcheck_schema.py` (`python selfcheck_schema.py`) is an assert-based self-check that builds a minimal valid record per platform and fails if a platform was added to one `build_quality` validator but forgotten in another, and that also covers the shared run-configuration layer (env-var precedence and parsing, `get_scrape_mode`, `keyword_matches`, `RecordFile`, the per-language routing in `analyze_text`, the non-Latin asset-extraction path, the Unicode dedup normalization, and `language_allowed`) — run it after touching the per-platform branches in `pipeline_utils.py` or anything in that config layer. `.venv` and `x-tweet-fetcher/` (a vendored git clone, its own project with its own tests) are not part of this project's code and should not be treated as such.

### Repository layout

Only code and config live in the repo root: the `*-scraper.py` scripts, `pipeline_utils.py`, `dedup_utils.py`, `selfcheck_schema.py`, `selfcheck_twtr_retry.py`, `run-scrapers.sh`, `requirements.txt`, `.env` / `.env.example`, `CLAUDE.md`, `.gitignore`. Everything else is in a directory named for what it holds:

| Directory | Holds | Constant |
|---|---|---|
| `keywords/` | `*-keywords.txt` search-term lists | `pipeline_utils.KEYWORDS_DIR` |
| `sources/` | `*-accounts.txt` / `*-channels.txt` / `*-subreddits.txt` trusted-source lists | `SOURCES_DIR` |
| `logs/` | every `*-scraper.log` (rotated 5MB x 3) | `LOG_DIR` |
| `dedup/` | `dedup-index.db` | `DEDUP_DIR` |
| `assets-registry/` | `asset-registry.json` (live) and `asset-registry.example.json` (template) | `ASSETS_REGISTRY_DIR`, `ASSET_REGISTRY_PATH` |
| `sessions/` | Telethon `*.session` login credentials | `SESSIONS_DIR` |

The output directories (`twtr-tweets/`, `yt-transcripts/`, `tel-transcripts/`, `reddit-posts/`, `tiktok-videos/`, `truth-posts/`) and `reports/` keep their names. Scrapers build their input paths from these constants rather than bare filenames, and `setup_logging` puts any bare log filename inside `LOG_DIR`, so moving a directory is a one-line change in `pipeline_utils.py`.

### Run configuration

Configuration is via environment variables (`.env`, documented knob-by-knob in `.env.example`) plus plain-text input files in the repo root — never CLI flags, and never an interactive prompt in an unattended run.

Every tunable constant at the top of a scraper is declared as `X = env_int("X", default)` (or `env_float` / `env_bool` / `env_set` / `env_range` / `env_str`, all in `pipeline_utils.py`). Each helper resolves `<PREFIX>_<NAME>` first, then the bare `<NAME>`, then the in-code default, so one `.env` line can retune every scraper while a prefixed line overrides a single one. Prefixes: `X_`, `YT_`, `TEL_`, `RD_`, `TT_`, `TS_`. A malformed value logs a warning and falls back to the default rather than killing a cron run — **keep it that way**, an unattended nightly run must never die on a typo. When adding a constant, add it as an `env_*` call and document it in `.env.example`; a bare literal is a constant an operator cannot reach.

`SCRAPE_MODE` (`keyword` | `accounts`) picks the discovery method for the run, read through `pipeline_utils.get_scrape_mode`:

- `accounts` — walk the trusted accounts/channels/subreddits and keep **every** post inside the time window. No keyword filtering, no candidate ranking, no relevance selection; relevance is left entirely to the asset-mapping stage, the trust model `tel-scraper.py` always used. Output is one file per account.
- `keyword` — the historical behaviour: search per keyword, scoped to the trusted accounts. Output is one file per keyword.

If `SCRAPE_MODE` is unset the scrapers only prompt when a terminal is attached; with no TTY they default to `keyword`, so a `bash`/cron wrapper never blocks on stdin. `tel-scraper.py` is account-driven by design and ignores the variable.

`MAX_PAST_MINUTES` is the collection window for **every** scraper, always in minutes (Telegram's old `TIME_WINDOW_MINUTES` was renamed to it), so a single `.env` value sets them all consistently.

Input files:

- `keywords/twtr-keywords.txt` / `keywords/yt-keywords.txt` / `keywords/reddit-keywords.txt` — required, one search keyword per line, script exits if missing.
- `sources/twtr-accounts.txt` / `sources/yt-channels.txt` — optional, auto-created with sane defaults (Reuters, Bloomberg, CNBC, BBC, CNN, Al Jazeera) if missing. `#`-prefixed lines are comments.
- `sources/reddit-subreddits.txt` — optional, auto-created with defaults (worldnews, news, business, economics, investing, energy) if missing. One subreddit per line; a leading `r/` is stripped.
- `sources/tel-channels.txt` — **required** for `tel-scraper.py`, one public channel username per line (`@` optional), `#`-prefixed lines are comments. Deliberately has no auto-created defaults, unlike the X/YouTube account lists: Telegram usernames for news outlets aren't reliably guessable, and a wrong guess would silently scrape the wrong channel instead of failing.
- `sources/tiktok-accounts.txt` / `sources/truth-accounts.txt` — **required** for `tiktok-scraper.py` / `truth-scraper.py`, one username per line (`@` optional). Same rationale as `sources/tel-channels.txt`: news outlets' handles on these platforms aren't reliably guessable and impersonator accounts are common, so there are deliberately no auto-created defaults.
- `keywords/tiktok-keywords.txt` / `keywords/truth-keywords.txt` — required only when those two scrapers run with `SCRAPE_MODE=keyword`; one keyword per line. In `accounts` mode they are not read at all.
- `assets-registry/asset-registry.json` (optional, gitignored) — overrides/extends the built-in asset registry in `pipeline_utils.py` without code changes; see `assets-registry/asset-registry.example.json` for the shape (`aliases`, `topics`, `description`, `context_inference`).

Each run is resumable/interruptible: results are written incrementally per keyword (or per account), not batched at the end.

`tel-scraper.py` additionally requires `TELEGRAM_API_ID` / `TELEGRAM_API_HASH` env vars (create an application at https://my.telegram.org). The first run does an interactive phone-number + login-code sign-in and writes a `sessions/<TELEGRAM_SESSION_NAME>.session` file; every later run — including unattended cron runs — reuses it without prompting. That session file is a live account credential and is gitignored along with `*.session-journal`.

`reddit-scraper.py` requires `REDDIT_CLIENT_ID` / `REDDIT_CLIENT_SECRET` for Reddit's classic Data API (the same OAuth2 API PRAW has always talked to — **not** `developers.reddit.com`/Devvit, which is a separate platform for apps that run inside Reddit itself, not for external read scripts). Since Reddit's Responsible Builder Policy (Nov 2025), `reddit.com/prefs/apps` no longer issues keys instantly — new access needs a manual-approval request via the form linked from Reddit's Data API wiki; credentials issued before Nov 2025 keep working unchanged. The client is put in `read_only` mode, so no Reddit account password and no write scope are ever involved. `truth-scraper.py` requires `TRUTHSOCIAL_USERNAME` / `TRUTHSOCIAL_PASSWORD` — Cloudflare rejects most unauthenticated reads, so the bearer token is required rather than optional — or `TRUTHSOCIAL_TOKEN` to reuse an existing token and skip the password grant. `tiktok-scraper.py` needs no credentials.

## Architecture

### Shared modules (`pipeline_utils.py`, `dedup_utils.py`)

Every platform scraper imports both and follows the same pipeline shape: search/discover → fetch → filter → dedup → score quality → write. Do not duplicate this logic into a new scraper — extend the shared modules instead so behavior (schema, quality scoring, dedup) stays identical across platforms.

`pipeline_utils.py`:
- `setup_logging` — console + rotating file logger (5MB × 3 backups) used by every scraper. Handlers go on the **root** logger so warnings raised inside `pipeline_utils`/`dedup_utils` land in the scraper's own log file; they previously did not, which meant "sentiment model unavailable" — the one line that explains why a whole run came back with null sentiment — never appeared anywhere. Chatty third-party loggers (`telethon`, `transformers`, `urllib3`, …) are pinned to WARNING so this does not turn the log into a library dump.
- `with_retry`, `RateLimiter` — retry/backoff decorator and a thread-safe global rate limiter, used to pace concurrent fetch workers against upstream rate limits.
- `env_str` / `env_int` / `env_float` / `env_bool` / `env_set` / `env_range` — the `.env`-backed config layer every scraper constant is declared through (see **Run configuration** above), and `get_scrape_mode`, which resolves `SCRAPE_MODE` without blocking an unattended run on stdin.
- `detect_language` / `is_english` — language-detection gate (py3langid) applied before saving any record.
- `analyze_text` — **the single entry point every scraper uses for text analysis**: returns `(sentiment, asset_mention)` for one record so the per-language handling is identical everywhere. **Nothing is translated anywhere in this pipeline** and no record carries a `translated_text` field: every record is analysed in its own language. Do not call `analyze_sentiment` / `extract_asset_mentions` directly from a scraper.
- `analyze_sentiment(text, lang)` — routes by language. English goes to FinBERT (`ProsusAI/finbert`, `SENTIMENT_MODEL` override); **every other language goes to a multilingual model** (`cardiffnlp/twitter-xlm-roberta-base-sentiment`, `MULTILINGUAL_SENTIMENT_MODEL` override, `"none"` to disable). FinBERT is English-only — fed Persian it tokenizes to mostly `[UNK]` and returns a label built out of noise, which is why the routing exists. Both models emit `{"label": positive|neutral|negative, "confidence": 0-1}`; `_SENTIMENT_LABEL_MAP` normalizes cardiffnlp's `LABEL_0/1/2` onto those words. Long text is chunked and the per-label probabilities averaged, because a 512-token window would otherwise judge a whole video by its opening ~380 words. Both fields are `null` when that language's model is unavailable — a degraded environment, never a fabricated score. A model that does not **fit on the GPU** is a resource condition, not a missing model: the load is retried pinned to CPU (`_is_oom_error`) rather than nulling sentiment for the entire run, mirroring `_demote_nli_to_cpu` on the NLI path. Without that, one other process holding VRAM silently nulls every record.
- `language_allowed(lang, confidence, allowed, min_confidence)` — the shared collection-language gate. A post is dropped **only when the detector is confident it is a language outside `allowed`**; a low-confidence verdict means the detector does not know, which is the normal outcome for a three-word post or a caption of hashtags, and those are kept. The old `lang not in ALLOWED or confidence < MIN` form dropped every short post from a trusted account.
- `load_asset_registry` / `extract_asset_mentions` — asset tagging. Loads the built-in registry (or `assets-registry/asset-registry.json` if present) and, via a shared NLI model (`MoritzLaurer/DeBERTa-v3-large-mnli-fever-anli-ling-wanli` by default, `ASSET_NLI_MODEL` env override — it must stay a **three-class** entailment/neutral/contradiction model; the two-class `zeroshot-v2.0` family has no contradiction label and silently turns the false-positive filter below into a no-op), scores which financial assets a record's text is actually about. Direct alias/cashtag mentions are kept unless the model actively *contradicts* the relevance claim with an entailment probability under `ASSET_DIRECT_MIN_CONFIDENCE` (default 0.10) — that is a false positive like "Shell" the noun or "gold" the colour, not a low-confidence hit. Context-only inference requires both the search topic and the record text to entail the asset, and equities require explicit `context_inference: true` in the registry entry to be inferred from sector language alone.
  - **The NLI model is English-only, so it is skipped entirely for non-Latin text** (`_is_latin_text`, plus an explicit non-Latin language list). Fed a Persian premise the model does not answer "unsure" — it returns a confident verdict on tokens it never saw, and that verdict used to *contradict* perfectly real mentions and delete them. A Persian record's direct alias/cashtag matches are therefore emitted as facts with a `null` confidence, and context-only inference is unavailable for it. This is what made a Persian Telegram post saying "USDT" come back with no `asset_mention` at all.
  - `_find_alias` matches on **Unicode** word boundaries (`(?<!\w)…(?!\w)`), not `[A-Za-z0-9_]`. With the ASCII class a Persian alias like `طلا` matched inside `طلایی` ("golden", the colour), because the following Persian letter is not an ASCII word character and so counted as a boundary.
  - The built-in registry carries **non-Latin aliases alongside the English ones** (`تتر`/`USDT`, `طلا`/gold, `نفت`/oil, `دلار`/USD, `بیت‌کوین`/Bitcoin, …) so alias matching works directly on Persian text without translation. It also covers the stablecoins and instruments the monitored market/signal channels actually trade — USDT, USDC, BNB, ADA, DOGE, TON, natural gas, and the Iranian rial/toman — none of which existed in it before.
- `RecordFile` / `parse_record_timestamp` / `keyword_matches` — output-file and keyword-filter helpers used by the account-driven platforms' keyword mode, where one pass over an account's timeline writes into several per-keyword files at once. `RecordFile` loads an existing file lazily, inserts new records in chronological position, and only rewrites the file if something was added.
- `get_whisper_model` / `transcribe_audio` — shared local Whisper (`faster-whisper`) transcription of a post's audio track, used by both `yt-scraper.py` and `tiktok-scraper.py`. The model is expensive to load and the CUDA circuit breaker (`_WHISPER_FAILURE_LIMIT`) is only meaningful if every scraper counts failures against the same state, which is why this lives here rather than in one scraper. Platform-specific yt-dlp options travel with the call via `extra_opts`, not inside the helper.
- `build_quality` — computes the record's `quality.quality_score` (0–100) by validating identity/URL consistency, content, timestamps, engagement/media, dedup, asset-mapping and sentiment fields, rather than a hand-weighted heuristic. The score is the harmonic mean of the per-dimension scores, so one weak dimension cannot hide behind many good fields.

`dedup_utils.py` — cross-source duplicate detection backed by SQLite (`dedup-index.db`, gitignored), safe for concurrent access by multiple scraper processes:
1. Exact-match layer: MD5 of normalized text. Normalization is **Unicode-aware** (`[^\w\s]` with `re.UNICODE`): the old ASCII-only `[^a-z0-9\s]` class erased Persian and Arabic text completely, normalizing every non-Latin record to the same empty string and making all of them exact duplicates of each other.
2. Near-duplicate layer: MinHash + LSH over word shingles (`JACCARD_THRESHOLD = 0.55`), catching paraphrased coverage of the same story across platforms.

This index is shared across all scrapers specifically so the same underlying story reported on X, YouTube, Telegram, Reddit, TikTok, and Truth Social isn't double-counted — always route new records for dedup through `dedup_utils`, never implement a scraper-local dedup check.

**Migration note.** Any `dedup-index.db` written before the Unicode normalization fix contains rows whose `content_hash` is the MD5 of the empty string (`d41d8cd98f00b204e9800998ecf8427e`) — one per non-Latin record, all in the same bogus duplicate group. They must be purged or they keep falsely matching new Persian records:

```sql
DELETE FROM dedup_records WHERE content_hash = 'd41d8cd98f00b204e9800998ecf8427e';
```

The LSH index is rebuilt from this table on every run, so deleting the rows repairs both dedup layers. Output files written before the fix also still carry a `translated_text` field and mostly-empty `asset_mention`; deleting the file and re-running regenerates it under the current schema.

**A duplicate is tagged, not dropped.** Every account-driven scraper (X, Telegram, TikTok, Truth Social) keeps the record and leave `deduplication.is_duplicate` on it for a downstream stage to collapse; the run is meant to collect everything a trusted account posted inside the window, and silently deleting records at write time made that impossible to verify. Each scraper logs how many it kept.

Dropping was also **unrecoverable**: `check_and_register` writes to the index *before* the output file is written, so a run that died mid-write left its records in the dedup index and invisible to every later run — they could never be collected again. Tagging makes that self-healing.

### Record schema

All scrapers emit the same JSON record shape (see the `record_id`, `Source`, `Content`, `time_stamps`, `asset_mention`, `sentiment`, `Engagement`, `media`, `deduplication`, `quality` fields documented in `twtr-scraper.md` / `yt-scraper.md`). `sentiment` is `{"label": "positive"|"neutral"|"negative", "confidence": 0-1}` — from FinBERT for an English record and from the multilingual model for any other language — or `{"label": null, "confidence": null}` when that language's model is unavailable. `Content.language` is the detected language. **There is no `translated_text` field** — the pipeline does not translate, and each record carries only its original text in its own language. `record_id` is `<Platform>_<author_or_channel_id>_<platform_native_id>`. `Content.Clean_text` is intentionally left empty by every scraper — populated by a separate downstream cleaning step, not by these scripts. `time_stamps.updated_at` must stay `null` unless the platform actually exposes an edit/modification timestamp; never substitute collection time for it. Telegram (`message.edit_date`), Reddit (`submission.edited`, which is literal `False` when never edited) and Truth Social (`edited_at`) do report one, so those three scrapers populate the field where the post was actually edited. TikTok exposes no such field, so its records always store `null`. `yt-scraper.py` reads yt-dlp's `modified_timestamp` and falls back to `null`, which satisfies the same rule — but yt-dlp's YouTube extractor does not currently emit that field, so every YouTube record stores `null`. Treat that branch as a guard, not as a second platform populating the field.

`build_quality` validates identity fields per-platform (`_valid_source_id`, `_valid_author_id`, `_valid_source_url`, `_record_id_consistent`, `_media_checks` in `pipeline_utils.py`). Adding a new platform means adding a branch to each of those plus an entry in `_PLATFORM_CONTENT_TYPES` (which drives both `valid_platform` and `expected_type`, and `_record_id_consistent` through `_KNOWN_PLATFORMS`) — a platform with no branch falls through to weak generic checks and silently scores lower. `_TITLED_PLATFORMS` marks the platforms whose posts carry a real title field and therefore get an extra `valid_title` check (YouTube, Reddit). Current `Content_type` per platform: X `tweet`, YouTube `video`, Telegram `message`, Reddit `post`, TikTok `video`, TruthSocial `post`. Run `python selfcheck_schema.py` after any change here.

Output naming follows the run's `SCRAPE_MODE`: keyword mode writes `twtr-tweets/twitter_<keyword>.json`, `yt-transcripts/youtube_<keyword>.json`, `reddit-posts/reddit_<keyword>.json`, `tiktok-videos/tiktok_<keyword>.json` and `truth-posts/truthsocial_<keyword>.json`; account mode writes the same files named after the account/channel/subreddit instead. `tel-transcripts/telegram_<channel>.json` is always per-channel. Each output directory is created on demand. Each run appends new records to the existing file and re-sorts the whole file chronologically by `published_at` — it never overwrites prior runs. Cross-source duplicates are appended with `deduplication.is_duplicate` set rather than skipped, so an accounts-mode run is a complete record of what the trusted source posted in the window.

**Accounts mode collects everything.** In `accounts` mode the trusted list is the only filter that matters: every post from a listed account inside `MAX_PAST_MINUTES` is kept, whatever its engagement, whether it is a reblog, whether it has media but no caption, and whether it duplicates something already seen. The only remaining drops are (a) a post the language detector is *confident* is outside `ALLOWED_LANGUAGES`, and (b) a post outside the time window. Both are counted and logged by every scraper — a scraper must never discard a candidate without saying so, because a silent drop is indistinguishable from a bug.

### Platform-specific pipelines

- **`twtr-scraper.py`**: X has no free search API, so the two modes use different discovery.
  - **Account mode** reads **X's public syndication timeline** (`https://syndication.twitter.com/srv/timeline-profile/screen-name/<user>`, the JSON behind embedded-timeline widgets) as its primary source. One unauthenticated request per account returns 20–100 **complete** tweet objects — `full_text`, `created_at`, engagement counts and the author's follower count — parsed out of the page's `__NEXT_DATA__` script tag, so those tweets need no per-tweet fetch at all and travel through `_fetch_and_write_tweets(prefetched=…)`. This replaced xtf's `fetch_timeline` as the first choice because that path needs a reachable Nitter instance or the browser driver: with neither configured (`XTF_NITTER` defaults to `http://127.0.0.1:8788`, a self-hosted instance that is normally not running) it reported `all_backends_failed` for every account and fell through to a DuckDuckGo search that found 0–3 tweets per account per *month*. The fallback chain is syndication → `xtf.fetch_timeline` → path-scoped `site:x.com/<username>` DDG search; a partial listing beats losing the account for the run.
  - **Keyword mode** goes through DuckDuckGo (`ddgs`) with `site:x.com <keyword>` queries, then fetches full tweet content via the vendored `x-tweet-fetcher` package (imported as `xtf`, FxTwitter backend). The trusted list **prioritises rather than filters**: `_ddg_tweet_refs` no longer drops untrusted authors at discovery time (credibility cannot be judged from a search result — follower and engagement counts are not in one), trusted authors are simply sorted first, and the decision happens after the fetch in `_is_credible`. An untrusted author is kept when the post clears **any one** of `X_UNTRUSTED_MIN_FOLLOWERS` (20 000), `X_UNTRUSTED_MIN_LIKES` (1 000) or `X_UNTRUSTED_MIN_VIEWS` (10 000); all three at 0 disables the gate. The old hard drop discarded ~90% of every search (`Dropped 26 result(s)… Found 2`).
  - Trusted-account scoping, where it still applies (the account-mode DDG fallback), is enforced in `_ddg_tweet_refs` on the parsed URLs, not in the query: DuckDuckGo is a web search and does not honour X's `from:` operator, so a `from:`-chained query returned untrusted authors anyway while diluting the query text. Never put the scoping back in the query string.
  - **The syndication CDN caches per account, and a cached response is not proof of freshness.** Its staleness varies wildly by account: measured on one run, `elonmusk` and `BBCBreaking` returned tweets from that same day while `MarkJCarney` was stuck ~9 months back and `marcorubio` ~11 days back, all HTTP 200 with valid JSON. The endpoint exposes no cursor or ETag to tell a complete cache from a stale one, so `discover_account_tweet_refs` uses a heuristic: when the newest tweet in the response is older than `X_ACCOUNT_MODE_FRESHNESS_MINUTES` (default 3 days), it **keeps** those tweets *and* supplements via xtf/DDG rather than believing the cache. This is why `refs` and `prefetched` can both be non-empty and `_fetch_and_write_tweets` merges them; the earlier either/or version made a stale cache look exactly like "this account posted nothing in the window". Note also that the widget's timeline excludes replies and is heavy on retweets, so it is never a complete account history.
  - **A refused syndication request is not an empty account.** `_syndication_timeline` raises `_SyndicationBlocked` on HTTP 429 *and* on a 200 whose body carries no `__NEXT_DATA__` payload (a challenge/interstitial page); only a parsed-but-empty `entries` list returns `[]`. Without this a 429'd account was dropped for the whole run under a `No recent tweets found` line, indistinguishable from an account that genuinely never posted.
  - **A rate-limited source never stalls the run.** While the cooldown is live, `_syndication_timeline` raises `_SyndicationBlocked` *immediately* — no sleep, and no request issued — and `discover_account_tweet_refs` falls straight through to xtf/DDG, returning a third value `syndication_blocked` alongside `(refs, prefetched)`. The account is still scraped from whatever works; being flagged means "could have done better", not "got nothing". `main()` collects those accounts and, only after the whole list is done, waits out the remaining cooldown once and re-runs them against the good source, for up to `X_SYNDICATION_RETRY_PASSES` (default 2) passes. **Do not reintroduce a sleep on the per-account path** — an earlier version slept the full cooldown inside `_syndication_timeline` and skipped the fallbacks, which held the entire 125-account list behind one blocked endpoint.
  - Inter-account pacing is adaptive for the same reason: `X_ACCOUNT_DELAY_RANGE` (syndication-sized, slow) applies only while syndication is actually in use, and `X_ACCOUNT_DELAY_BLOCKED_RANGE` (default `2,5`) applies while it is in cooldown, since the loop is then only calling xtf/DDG, which carry their own limiters.
  - **X's syndication 429 is long and carries no `Retry-After`.** Measured by polling a single account every 30s after a run tripped the limit: the endpoint refused continuously and cleared at **429 s (~7.2 min)**. One 429 therefore arms a process-wide cooldown (`X_SYNDICATION_COOLDOWN_SECONDS`, default 600 — the measurement plus margin) that every later syndication call waits out, because `ACCOUNT_DELAY_RANGE`'s few seconds only guarantees the next account hits the same live block. 429s are **not** retried in place — `with_retry` on this function covers transport faults only — since a multi-minute block outlasts any per-request backoff; the deferred-retry passes are the recovery path instead.
  - **The syndication rate budget sets the run length, and pacing under it is faster than pacing over it.** Measured: ~10–11 requests are served before the endpoint refuses (the 429 in one run landed on the 11th account; a 10-request burst at 5 s spacing passed clean), and the block then lasts ~429 s — roughly one request per 43 s sustained. `X_ACCOUNT_DELAY_RANGE` therefore defaults to `38,48`, not the old `3,6`: at ~4.5 s spacing a 125-account list costs ~10 accounts per 600 s cooldown cycle (~134 min, with accounts bouncing into retry passes), while pacing under the budget costs ~90 min with no blocks at all. The old default provably could not get past account ~11 of 125. Lower it only for a short account list.
  - **An empty `entries` list is not a block, and some accounts always return one.** `@SecDef` and `@SecBessent` return a valid `__NEXT_DATA__` payload with `entries: []` even with the rate limit fully clear — the embedded-widget endpoint simply does not serve them. The tell is `pageProps.latest_tweet_id`, present on every account that returns tweets and absent on these. They therefore fall through to xtf/DDG on every run and must **not** be treated as `_SyndicationBlocked`, or they would consume every retry pass forever.
  - `_ddg_timelimit()` derives DuckDuckGo's coarse `timelimit` (`d`/`w`/`m`/`y`) from `MAX_PAST_MINUTES`. It was pinned to `"w"`, so a 30-day run only ever searched the last 7 days.
  - `_build_engagement` / `_tweet_metrics` / `_extract_media_info` accept **both** field spellings, because fxtwitter returns `likes`/`replies`/`retweets` while the syndication JSON returns X's v1.1 `favorite_count`/`reply_count`/`retweet_count` and puts attachments under `entities`/`extended_entities`. Syndication reports no view count, so `Views` is 0 there rather than guessed.
  - Both the DDG search path and the X fetch path are unofficial/unauthenticated and carry real exposure to rate-limiting/blocking — this is why the script has retry/backoff and per-keyword pacing delays baked in rather than being optional.
- **`yt-scraper.py`**: Discovers candidate videos via `yt-dlp` search filtered to trusted channels (keyword mode) or by listing each channel's uploads tab directly (account mode, `resolve_channel_id` + `list_channel_uploads`), then extracts spoken content with a two-tier strategy: YouTube's own captions first (`youtube-transcript-api`, fast/free), falling back to local Whisper transcription (`faster-whisper`) only when no captions exist. Whisper uses a multilingual model + `task="translate"` (not an English-only model) so non-English audio is still handled correctly. Requires `ffmpeg` on `PATH` for the Whisper fallback's audio postprocessing. GPU (CUDA) is used automatically if available and falls back to CPU after repeated library-load failures via a circuit breaker (`_WHISPER_FAILURE_LIMIT`) — this is a graceful perf degradation, not an error condition to "fix" by making GPU mandatory.
- **`tel-scraper.py`**: There is no keyword search step at all — it walks each trusted channel's recent history directly and keeps every message inside the `MAX_PAST_MINUTES` window (default 1440), so relevance filtering is left entirely to the asset-mapping stage. This is the only scraper that ignores `SCRAPE_MODE`. Auth is Telethon MTProto as a *user account*, not the Bot API, because a bot can only read channels it was added to as admin. Channels are processed **sequentially, not through a `ThreadPoolExecutor`** like X/YouTube: one MTProto session gains nothing from parallel requests and concurrent reads raise the flood-ban risk for the account — don't "optimize" this into a thread pool. Flood control is handled by `_with_flood_retry`, which sleeps for the exact duration Telegram dictates (`FloodWaitError.seconds`) rather than the fixed backoff schedule `pipeline_utils.with_retry` provides; short waits under `FLOOD_SLEEP_THRESHOLD` are absorbed by Telethon itself.
  - `REFRESH_EDITED_MESSAGES` (default `True`) re-scans the whole window so edits to already-saved posts refresh the stored record in place (text, `updated_at`, assets, and quality are recomputed; `published_at` and therefore sort position never change). Setting it `False` switches to a cheaper append-only mode that passes the newest stored message ID as Telethon's `min_id` and never sees an edit.
  - `ALLOWED_LANGUAGES` defaults to `{"en", "fa"}` here as it now does everywhere: most trusted Telegram channels post in Persian, and since Persian records are scored in Persian via `analyze_text` there is no reason for any scraper to drop them.
  - Channels without a public username are skipped — a stable `t.me/<username>/<id>` URL can't be built for them, and the schema's URL/identity checks require one.

- **`reddit-scraper.py`**: Uses the official API through `praw` in `read_only` mode (client-credentials grant, no user password, no write scope). In keyword mode all trusted subreddits are searched in one call per keyword via Reddit's `sub1+sub2+...` multireddit path rather than one call per subreddit per keyword; in account mode `list_new_submissions` reads each subreddit's chronological `/new` listing and keeps everything inside the window. Both modes share `_merge_submissions`, so the same submission produces a byte-identical record either way. The **subreddit plays the author role** in the schema (`author_id` = subreddit, `author_name` = `Source_name` = `r/<subreddit>`), the same way a channel does for Telegram/YouTube, because the subreddit is the trusted source being monitored. Link posts have no body, so `raw_text` falls back to the title — that is a complete post, not a truncated extraction. Reddit's `score` is a net value that can go negative, so engagement counts are clamped at 0.
- **`tiktok-scraper.py`**: TikTok has no free search API, so discovery is account-driven in **both** modes: one cheap `extract_flat` listing per account, then a full `yt-dlp` extraction only for videos not already stored. Keyword mode does not query a search endpoint — the trusted accounts *are* the search space — it walks the same listings and files each video under the first keyword its description/title/transcript matches (`pipeline_utils.keyword_matches`), dropping videos that match none. Do not "fix" this into a hashtag/search-page crawl: `tiktok.com/tag/<kw>` is unscoped to the trusted accounts and would let impersonator content into a trusted-source dataset. Text uses the same two tiers as YouTube — TikTok's own auto-captions (written to a temp dir by the same request that fetches the metadata, so tier 1 costs no extra round trip) then `pipeline_utils.transcribe_audio`. If both fail the video description is stored instead so the post isn't lost, but the record is flagged with `complete_raw_text=False` plus an extraction error, because the spoken content genuinely wasn't captured. Auto-captions repeat each line across consecutive cues as the caption box scrolls, which is why `_vtt_to_text` collapses consecutive repeats. Accounts are processed **sequentially** — TikTok blocks aggressively on bursts.
  - A video older than the window is **skipped, not `break`ed on**. An account's *pinned* videos are listed first and can be years old, so the first out-of-window video is no proof the rest are older; the old `break` ended the whole account after one old pin. The loop now walks the full listing (bounded by `MAX_VIDEOS_PER_ACCOUNT`) and logs `Skipped N video(s) older than …`.
  - Every other skip is counted and logged too (`skipped_no_text`, `skipped_no_keyword`, `duplicates_kept`). A run that collects one video out of thirty is now distinguishable from a run that silently lost twenty-nine — which was the actual reporting problem, since `@realdonaldtrump` really did post only one TikTok inside a 30-day window.
- **`truth-scraper.py`**: Truth Social is a Mastodon fork, so it is read through the standard Mastodon endpoints (`/api/v1/accounts/lookup`, `/api/v1/accounts/<id>/statuses`) over stdlib `urllib` — no HTTP dependency is needed. One password-grant login per run yields a `read`-scoped bearer token. `CLIENT_ID`/`CLIENT_SECRET` are the site's public web-client values shipped in its JavaScript bundle (env-overridable), not secrets — the account password is read from the environment only. Statuses are paged newest-first with `max_id` until the time window or `MAX_POSTS_PER_ACCOUNT`. Like TikTok, keyword mode filters the trusted accounts' own timelines rather than calling `/api/v2/search`, which is unscoped to the trusted accounts and Cloudflare-gated. The server's reported `username` is preferred over the configured one so a renamed account stays consistent with its `record_id` and URL.
  - Paging **must not** stop on a short page. Truth Social caps a page at 20 statuses however many were requested, so the old `len(page) < limit` break ended every account after its first page and capped a 30-day window at 20 posts. Only an empty page, the time cutoff, `MAX_POSTS_PER_ACCOUNT`, or `TS_ACCOUNT_TIME_BUDGET` ends the walk.
  - **Reblogs are collected**, not skipped. A reblog is a post the trusted account chose to amplify. Text and media come from the reblogged status (`content_status`), while identity, id, URL and timestamps stay this account's, so the record is "@account reposted this" and remains addressable at this account's own permalink.
  - **Media-only posts are collected.** A post with an empty HTML body still came from a trusted account inside the window; `_media_alt_text` falls back to the spoiler/CW line and per-attachment alt text, and the record is flagged `complete_raw_text=False` with an extraction error when no text exists at all. Reblogs plus media-only posts were most of the roughly half of each account's output that used to vanish with no log line.
  - `TS_EXCLUDE_REPLIES` defaults to **false** — replies are posts the account made too.
  - Cloudflare fronts this API and answers a client it considers too eager by **stalling** the connection rather than refusing it, so a socket timeout alone never bounds a run. Three things do: `_RetryableApiError` + `with_retry` (retry 429/5xx/timeouts with backoff, never a 401/403/404 verdict), `TS_API_TIMEOUT` per call, and `TS_ACCOUNT_TIME_BUDGET` as a wall-clock ceiling on paging one account. A throttled account costs the run one bounded pause and keeps whatever it already collected, instead of hanging an unattended run indefinitely.
