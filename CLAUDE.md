# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

Do not make any changes until you have 95% confidence in what you need to build. Ask me follow-up questions until you reach that confidence.

## What this is

A set of independent scrapers that collect financial/energy-market news coverage from social platforms (X/Twitter, YouTube, Telegram, Reddit, TikTok, Truth Social) into a shared JSON record schema, for downstream sentiment/NLP processing (e.g. FinBERT). Each platform scraper is a standalone script driven by keyword/account config files, sharing two local modules for logging, dedup, and quality scoring.

## Running the scrapers

```bash
pip install -r requirements.txt --break-system-packages
python twtr-scraper.py     # X/Twitter — no CLI args
python yt-scraper.py       # YouTube — no CLI args
python tel-scraper.py      # Telegram — no CLI args, needs TELEGRAM_API_ID/TELEGRAM_API_HASH
python reddit-scraper.py   # Reddit — no CLI args, needs REDDIT_CLIENT_ID/REDDIT_CLIENT_SECRET
python tiktok-scraper.py   # TikTok — no CLI args
python truth-scraper.py    # Truth Social — no CLI args, needs TRUTHSOCIAL_USERNAME/TRUTHSOCIAL_PASSWORD
```

There is no test suite, build step, or linter configured in this repo. The one exception is `selfcheck_schema.py` (`python selfcheck_schema.py`), an assert-based self-check that builds a minimal valid record per platform and fails if a platform was added to one `build_quality` validator but forgotten in another, and that also covers the shared run-configuration layer (env-var precedence and parsing, `get_scrape_mode`, `keyword_matches`, `RecordFile`, and the fa/en routing in `analyze_text`) — run it after touching the per-platform branches in `pipeline_utils.py` or anything in that config layer. `.venv` and `x-tweet-fetcher/` (a vendored git clone, its own project with its own tests) are not part of this project's code and should not be treated as such.

### Run configuration

Configuration is via environment variables (`.env`, documented knob-by-knob in `.env.example`) plus plain-text input files in the repo root — never CLI flags, and never an interactive prompt in an unattended run.

Every tunable constant at the top of a scraper is declared as `X = env_int("X", default)` (or `env_float` / `env_bool` / `env_set` / `env_range` / `env_str`, all in `pipeline_utils.py`). Each helper resolves `<PREFIX>_<NAME>` first, then the bare `<NAME>`, then the in-code default, so one `.env` line can retune every scraper while a prefixed line overrides a single one. Prefixes: `X_`, `YT_`, `TEL_`, `RD_`, `TT_`, `TS_`. A malformed value logs a warning and falls back to the default rather than killing a cron run — **keep it that way**, an unattended nightly run must never die on a typo. When adding a constant, add it as an `env_*` call and document it in `.env.example`; a bare literal is a constant an operator cannot reach.

`SCRAPE_MODE` (`keyword` | `accounts`) picks the discovery method for the run, read through `pipeline_utils.get_scrape_mode`:

- `accounts` — walk the trusted accounts/channels/subreddits and keep **every** post inside the time window. No keyword filtering, no candidate ranking, no relevance selection; relevance is left entirely to the asset-mapping stage, the trust model `tel-scraper.py` always used. Output is one file per account.
- `keyword` — the historical behaviour: search per keyword, scoped to the trusted accounts. Output is one file per keyword.

If `SCRAPE_MODE` is unset the scrapers only prompt when a terminal is attached; with no TTY they default to `keyword`, so a `bash`/cron wrapper never blocks on stdin. `tel-scraper.py` is account-driven by design and ignores the variable.

`MAX_PAST_MINUTES` is the collection window for **every** scraper, always in minutes (Telegram's old `TIME_WINDOW_MINUTES` was renamed to it), so a single `.env` value sets them all consistently.

Input files:

- `twtr-keywords.txt` / `yt-keywords.txt` / `reddit-keywords.txt` — required, one search keyword per line, script exits if missing.
- `twtr-accounts.txt` / `yt-channels.txt` — optional, auto-created with sane defaults (Reuters, Bloomberg, CNBC, BBC, CNN, Al Jazeera) if missing. `#`-prefixed lines are comments.
- `reddit-subreddits.txt` — optional, auto-created with defaults (worldnews, news, business, economics, investing, energy) if missing. One subreddit per line; a leading `r/` is stripped.
- `tel-channels.txt` — **required** for `tel-scraper.py`, one public channel username per line (`@` optional), `#`-prefixed lines are comments. Deliberately has no auto-created defaults, unlike the X/YouTube account lists: Telegram usernames for news outlets aren't reliably guessable, and a wrong guess would silently scrape the wrong channel instead of failing.
- `tiktok-accounts.txt` / `truth-accounts.txt` — **required** for `tiktok-scraper.py` / `truth-scraper.py`, one username per line (`@` optional). Same rationale as `tel-channels.txt`: news outlets' handles on these platforms aren't reliably guessable and impersonator accounts are common, so there are deliberately no auto-created defaults.
- `tiktok-keywords.txt` / `truth-keywords.txt` — required only when those two scrapers run with `SCRAPE_MODE=keyword`; one keyword per line. In `accounts` mode they are not read at all.
- `asset-registry.json` (optional, gitignored) — overrides/extends the built-in asset registry in `pipeline_utils.py` without code changes; see `asset-registry.example.json` for the shape (`aliases`, `topics`, `description`, `context_inference`).

Each run is resumable/interruptible: results are written incrementally per keyword (or per account), not batched at the end.

`tel-scraper.py` additionally requires `TELEGRAM_API_ID` / `TELEGRAM_API_HASH` env vars (create an application at https://my.telegram.org). The first run does an interactive phone-number + login-code sign-in and writes a `<TELEGRAM_SESSION_NAME>.session` file; every later run — including unattended cron runs — reuses it without prompting. That session file is a live account credential and is gitignored along with `*.session-journal`.

`reddit-scraper.py` requires `REDDIT_CLIENT_ID` / `REDDIT_CLIENT_SECRET` for Reddit's classic Data API (the same OAuth2 API PRAW has always talked to — **not** `developers.reddit.com`/Devvit, which is a separate platform for apps that run inside Reddit itself, not for external read scripts). Since Reddit's Responsible Builder Policy (Nov 2025), `reddit.com/prefs/apps` no longer issues keys instantly — new access needs a manual-approval request via the form linked from Reddit's Data API wiki; credentials issued before Nov 2025 keep working unchanged. The client is put in `read_only` mode, so no Reddit account password and no write scope are ever involved. `truth-scraper.py` requires `TRUTHSOCIAL_USERNAME` / `TRUTHSOCIAL_PASSWORD` — Cloudflare rejects most unauthenticated reads, so the bearer token is required rather than optional — or `TRUTHSOCIAL_TOKEN` to reuse an existing token and skip the password grant. `tiktok-scraper.py` needs no credentials.

## Architecture

### Shared modules (`pipeline_utils.py`, `dedup_utils.py`)

Every platform scraper imports both and follows the same pipeline shape: search/discover → fetch → filter → dedup → score quality → write. Do not duplicate this logic into a new scraper — extend the shared modules instead so behavior (schema, quality scoring, dedup) stays identical across platforms.

`pipeline_utils.py`:
- `setup_logging` — console + rotating file logger (5MB × 3 backups) used by every scraper.
- `with_retry`, `RateLimiter` — retry/backoff decorator and a thread-safe global rate limiter, used to pace concurrent fetch workers against upstream rate limits.
- `env_str` / `env_int` / `env_float` / `env_bool` / `env_set` / `env_range` — the `.env`-backed config layer every scraper constant is declared through (see **Run configuration** above), and `get_scrape_mode`, which resolves `SCRAPE_MODE` without blocking an unattended run on stdin.
- `detect_language` / `is_english` — language-detection gate (py3langid) applied before saving any record.
- `analyze_text` — **the single entry point every scraper uses for text analysis**: returns `(translated_text, sentiment, asset_mention)` for one record so the fa/en handling is identical everywhere. English records are scored directly. Persian records are translated once (`translate_fa_to_en`, an opus-mt Iranian-languages model) and both FinBERT and the asset stage then read the *translation* — the registry aliases and the NLI model are English-only, so a Persian record scored on its raw text would silently report no assets and no sentiment. If the translation model is unavailable the original text is still analysed, keeping cashtags and Latin symbols matchable. Do not call `analyze_sentiment` / `extract_asset_mentions` directly from a scraper; that is how the Persian path gets bypassed.
- `analyze_sentiment` — FinBERT (`ProsusAI/finbert`, `SENTIMENT_MODEL` override) producing `{"label": positive|neutral|negative, "confidence": 0-1}`. Long text is chunked and the per-label probabilities averaged, because FinBERT's 512-token window would otherwise judge a whole video by its opening ~380 words. Both fields are `null` when the model is unavailable — a degraded environment, never a fabricated score.
- `load_asset_registry` / `extract_asset_mentions` — asset tagging. Loads the built-in registry (or `asset-registry.json` if present) and, via a shared NLI model (`MoritzLaurer/DeBERTa-v3-large-mnli-fever-anli-ling-wanli` by default, `ASSET_NLI_MODEL` env override — it must stay a **three-class** entailment/neutral/contradiction model; the two-class `zeroshot-v2.0` family has no contradiction label and silently turns the false-positive filter below into a no-op), scores which financial assets a record's text is actually about. Direct alias/cashtag mentions are kept unless the model actively *contradicts* the relevance claim with an entailment probability under `ASSET_DIRECT_MIN_CONFIDENCE` (default 0.10) — that is a false positive like "Shell" the noun or "gold" the colour, not a low-confidence hit. Context-only inference requires both the search topic and the record text to entail the asset, and equities require explicit `context_inference: true` in the registry entry to be inferred from sector language alone.
- `RecordFile` / `parse_record_timestamp` / `keyword_matches` — output-file and keyword-filter helpers used by the account-driven platforms' keyword mode, where one pass over an account's timeline writes into several per-keyword files at once. `RecordFile` loads an existing file lazily, inserts new records in chronological position, and only rewrites the file if something was added.
- `get_whisper_model` / `transcribe_audio` — shared local Whisper (`faster-whisper`) transcription of a post's audio track, used by both `yt-scraper.py` and `tiktok-scraper.py`. The model is expensive to load and the CUDA circuit breaker (`_WHISPER_FAILURE_LIMIT`) is only meaningful if every scraper counts failures against the same state, which is why this lives here rather than in one scraper. Platform-specific yt-dlp options travel with the call via `extra_opts`, not inside the helper.
- `build_quality` — computes the record's `quality.quality_score` (0–100) by validating identity/URL consistency, content (including `translated_text` being present exactly for Persian records), timestamps, engagement/media, dedup, asset-mapping and sentiment fields, rather than a hand-weighted heuristic. The score is the harmonic mean of the per-dimension scores, so one weak dimension cannot hide behind many good fields.

`dedup_utils.py` — cross-source duplicate detection backed by SQLite (`dedup-index.db`, gitignored), safe for concurrent access by multiple scraper processes:
1. Exact-match layer: MD5 of normalized text.
2. Near-duplicate layer: MinHash + LSH over word shingles (`JACCARD_THRESHOLD = 0.55`), catching paraphrased coverage of the same story across platforms.

This index is shared across all scrapers specifically so the same underlying story reported on X, YouTube, Telegram, Reddit, TikTok, and Truth Social isn't double-counted — always route new records for dedup through `dedup_utils`, never implement a scraper-local dedup check.

### Record schema

All scrapers emit the same JSON record shape (see the `record_id`, `Source`, `Content`, `time_stamps`, `asset_mention`, `sentiment`, `Engagement`, `media`, `deduplication`, `quality` fields documented in `twtr-scraper.md` / `yt-scraper.md`). `sentiment` is `{"label": "positive"|"neutral"|"negative", "confidence": 0-1}` from FinBERT, or `{"label": null, "confidence": null}` when the model is unavailable. `Content.language` is the detected language and `Content.translated_text` carries the English translation of a Persian record (and stays `null` for an English one) — both languages are kept, the original is never overwritten by its translation. `record_id` is `<Platform>_<author_or_channel_id>_<platform_native_id>`. `Content.Clean_text` is intentionally left empty by every scraper — populated by a separate downstream cleaning step, not by these scripts. `time_stamps.updated_at` must stay `null` unless the platform actually exposes an edit/modification timestamp; never substitute collection time for it. Telegram (`message.edit_date`), Reddit (`submission.edited`, which is literal `False` when never edited) and Truth Social (`edited_at`) do report one, so those three scrapers populate the field where the post was actually edited. TikTok exposes no such field, so its records always store `null`. `yt-scraper.py` reads yt-dlp's `modified_timestamp` and falls back to `null`, which satisfies the same rule — but yt-dlp's YouTube extractor does not currently emit that field, so every YouTube record stores `null`. Treat that branch as a guard, not as a second platform populating the field.

`build_quality` validates identity fields per-platform (`_valid_source_id`, `_valid_author_id`, `_valid_source_url`, `_record_id_consistent`, `_media_checks` in `pipeline_utils.py`). Adding a new platform means adding a branch to each of those plus an entry in `_PLATFORM_CONTENT_TYPES` (which drives both `valid_platform` and `expected_type`, and `_record_id_consistent` through `_KNOWN_PLATFORMS`) — a platform with no branch falls through to weak generic checks and silently scores lower. `_TITLED_PLATFORMS` marks the platforms whose posts carry a real title field and therefore get an extra `valid_title` check (YouTube, Reddit). Current `Content_type` per platform: X `tweet`, YouTube `video`, Telegram `message`, Reddit `post`, TikTok `video`, TruthSocial `post`. Run `python selfcheck_schema.py` after any change here.

Output naming follows the run's `SCRAPE_MODE`: keyword mode writes `twtr-tweets/twitter_<keyword>.json`, `yt-transcripts/youtube_<keyword>.json`, `reddit-posts/reddit_<keyword>.json`, `tiktok-videos/tiktok_<keyword>.json` and `truth-posts/truthsocial_<keyword>.json`; account mode writes the same files named after the account/channel/subreddit instead. `tel-transcripts/telegram_<channel>.json` is always per-channel. Each output directory is created on demand. Each run appends new non-duplicate records to the existing file and re-sorts the whole file chronologically by `published_at` — it never overwrites prior runs.

### Platform-specific pipelines

- **`twtr-scraper.py`**: In keyword mode X has no free search API, so discovery goes through DuckDuckGo (`ddgs`) using `site:x.com <keyword>` queries; in account mode `discover_account_tweet_refs` pages the account's own timeline through `xtf` up to `ACCOUNT_MODE_FETCH_LIMIT`, and falls back to a path-scoped `site:x.com/<username>` DDG search when every xtf backend is down (a partial listing beats losing the account for that run). Trusted-account scoping is enforced in `_ddg_tweet_refs` on the parsed URLs, not in the query: DuckDuckGo is a web search and does not honour X's `from:` operator, so a `from:`-chained query returned untrusted authors anyway while diluting the query text. Never put the scoping back in the query string and drop the filter. Either way full tweet content is then fetched via the vendored `x-tweet-fetcher` package (imported as `xtf`). Both the DDG search path and the X fetch path are unofficial/unauthenticated and carry real exposure to rate-limiting/blocking — this is why the script has retry/backoff and per-keyword pacing delays baked in rather than being optional.
- **`yt-scraper.py`**: Discovers candidate videos via `yt-dlp` search filtered to trusted channels (keyword mode) or by listing each channel's uploads tab directly (account mode, `resolve_channel_id` + `list_channel_uploads`), then extracts spoken content with a two-tier strategy: YouTube's own captions first (`youtube-transcript-api`, fast/free), falling back to local Whisper transcription (`faster-whisper`) only when no captions exist. Whisper uses a multilingual model + `task="translate"` (not an English-only model) so non-English audio is still handled correctly. Requires `ffmpeg` on `PATH` for the Whisper fallback's audio postprocessing. GPU (CUDA) is used automatically if available and falls back to CPU after repeated library-load failures via a circuit breaker (`_WHISPER_FAILURE_LIMIT`) — this is a graceful perf degradation, not an error condition to "fix" by making GPU mandatory.
- **`tel-scraper.py`**: There is no keyword search step at all — it walks each trusted channel's recent history directly and keeps every message inside the `MAX_PAST_MINUTES` window (default 1440), so relevance filtering is left entirely to the asset-mapping stage. This is the only scraper that ignores `SCRAPE_MODE`. Auth is Telethon MTProto as a *user account*, not the Bot API, because a bot can only read channels it was added to as admin. Channels are processed **sequentially, not through a `ThreadPoolExecutor`** like X/YouTube: one MTProto session gains nothing from parallel requests and concurrent reads raise the flood-ban risk for the account — don't "optimize" this into a thread pool. Flood control is handled by `_with_flood_retry`, which sleeps for the exact duration Telegram dictates (`FloodWaitError.seconds`) rather than the fixed backoff schedule `pipeline_utils.with_retry` provides; short waits under `FLOOD_SLEEP_THRESHOLD` are absorbed by Telethon itself.
  - `REFRESH_EDITED_MESSAGES` (default `True`) re-scans the whole window so edits to already-saved posts refresh the stored record in place (text, `updated_at`, assets, and quality are recomputed; `published_at` and therefore sort position never change). Setting it `False` switches to a cheaper append-only mode that passes the newest stored message ID as Telethon's `min_id` and never sees an edit.
  - `ALLOWED_LANGUAGES` defaults to `{"en", "fa"}` here as it now does everywhere: most trusted Telegram channels post in Persian, and since Persian records are translated and scored via `analyze_text` there is no reason for any scraper to drop them.
  - Channels without a public username are skipped — a stable `t.me/<username>/<id>` URL can't be built for them, and the schema's URL/identity checks require one.

- **`reddit-scraper.py`**: Uses the official API through `praw` in `read_only` mode (client-credentials grant, no user password, no write scope). In keyword mode all trusted subreddits are searched in one call per keyword via Reddit's `sub1+sub2+...` multireddit path rather than one call per subreddit per keyword; in account mode `list_new_submissions` reads each subreddit's chronological `/new` listing and keeps everything inside the window. Both modes share `_merge_submissions`, so the same submission produces a byte-identical record either way. The **subreddit plays the author role** in the schema (`author_id` = subreddit, `author_name` = `Source_name` = `r/<subreddit>`), the same way a channel does for Telegram/YouTube, because the subreddit is the trusted source being monitored. Link posts have no body, so `raw_text` falls back to the title — that is a complete post, not a truncated extraction. Reddit's `score` is a net value that can go negative, so engagement counts are clamped at 0.
- **`tiktok-scraper.py`**: TikTok has no free search API, so discovery is account-driven in **both** modes: one cheap `extract_flat` listing per account, then a full `yt-dlp` extraction only for videos not already stored. Keyword mode does not query a search endpoint — the trusted accounts *are* the search space — it walks the same listings and files each video under the first keyword its description/title/transcript matches (`pipeline_utils.keyword_matches`), dropping videos that match none. Do not "fix" this into a hashtag/search-page crawl: `tiktok.com/tag/<kw>` is unscoped to the trusted accounts and would let impersonator content into a trusted-source dataset. Text uses the same two tiers as YouTube — TikTok's own auto-captions (written to a temp dir by the same request that fetches the metadata, so tier 1 costs no extra round trip) then `pipeline_utils.transcribe_audio`. If both fail the video description is stored instead so the post isn't lost, but the record is flagged with `complete_raw_text=False` plus an extraction error, because the spoken content genuinely wasn't captured. Auto-captions repeat each line across consecutive cues as the caption box scrolls, which is why `_vtt_to_text` collapses consecutive repeats. Accounts are processed **sequentially** — TikTok blocks aggressively on bursts.
- **`truth-scraper.py`**: Truth Social is a Mastodon fork, so it is read through the standard Mastodon endpoints (`/api/v1/accounts/lookup`, `/api/v1/accounts/<id>/statuses`) over stdlib `urllib` — no HTTP dependency is needed. One password-grant login per run yields a `read`-scoped bearer token. `CLIENT_ID`/`CLIENT_SECRET` are the site's public web-client values shipped in its JavaScript bundle (env-overridable), not secrets — the account password is read from the environment only. Statuses are paged newest-first with `max_id` until the time window or `MAX_POSTS_PER_ACCOUNT`. Like TikTok, keyword mode filters the trusted accounts' own timelines rather than calling `/api/v2/search`, which is unscoped to the trusted accounts and Cloudflare-gated. Reblogs are skipped (the original post is the record worth storing) and the server's reported `username` is preferred over the configured one so a renamed account stays consistent with its `record_id` and URL.

### x-tweet-fetcher

`x-tweet-fetcher/` is a vendored clone of a separate upstream project (its own git repo, README, tests, SKILL.md) that provides the `xtf` Python package used by `twtr-scraper.py` to fetch tweet content without X's paid API (via FxTwitter for single tweets, a Nitter instance for timelines/search, and a browser driver for lists/articles). Treat it as a third-party dependency, not project code — don't modify it as part of scraper feature work; if it needs a fix, that's a separate concern from this repo's scrapers.

## Data sensitivity

All keyword/account/channel/subreddit list files (`twtr-keywords.txt`, `twtr-accounts.txt`, `yt-keywords.txt`, `yt-channels.txt`, `tel-channels.txt`, `reddit-keywords.txt`, `reddit-subreddits.txt`, `tiktok-accounts.txt`, `tiktok-keywords.txt`, `truth-accounts.txt`, `truth-keywords.txt`) and all `*-scraper.log` files are gitignored — they can reveal what topics/entities are being monitored. `dedup-index.db` and the `twtr-tweets/` / `yt-transcripts/` / `tel-transcripts/` / `reddit-posts/` / `tiktok-videos/` / `truth-posts/` output directories are also gitignored since they're regenerable run artifacts, not source.

`*.session` / `*.session-journal` (Telethon login sessions) are gitignored and must stay that way — a session file is a live authenticated credential for the Telegram account that created it, and anyone holding it can act as that account. `TELEGRAM_API_ID` / `TELEGRAM_API_HASH` are read from the environment for the same reason and must never be hardcoded into `tel-scraper.py`. `pipeline_utils.py` calls `load_dotenv()` on import (via `python-dotenv`), so every scraper picks up credentials **and all run configuration** from a gitignored `.env` file in the repo root without needing its own loader; a real shell `export` still takes precedence over `.env`. `.env.example` is the committed, credential-free template documenting every knob — keep it in sync when adding a setting, and never let a real value land in it. The same applies to `REDDIT_CLIENT_ID` / `REDDIT_CLIENT_SECRET` and `TRUTHSOCIAL_USERNAME` / `TRUTHSOCIAL_PASSWORD` / `TRUTHSOCIAL_TOKEN`: those are account credentials and stay in the environment. `TRUTHSOCIAL_CLIENT_ID` / `TRUTHSOCIAL_CLIENT_SECRET` are the deliberate exception — they are public web-client values, and their defaults in `truth-scraper.py` are not a secret leak.
